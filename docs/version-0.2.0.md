## 两种记忆的边界

对话历史是 `list[Message]`，用于把前文重新发送给模型。它存在内存中，程序退出或 /new 后清空，不是持久化聊天记录。

长期记忆是 SQLite 的 memories 表，保存 id、content、created_at。id 由 UUID 生成，时间使用 UTC ISO 格式。程序重新启动后连接同一个 `data/memory.db` 即可读取；并非模型参数发生了变化。

MemoryItem 使用 frozen dataclass。SQLiteMemoryStore 每次操作建立并关闭连接，写操作明确 commit，SQL 值通过参数绑定传入。数据库能力由 Python 标准库 sqlite3 提供，项目实现的是数据结构、SQL 操作和上层调用组织。

## 谁调用谁

```text
main.py：读取输入
  ├─ /quit、/new、/history → 入口直接处理
  ├─ 明确记忆命令或支持的固定表达
  │    → handle_memory_command
  │    → SQLiteMemoryStore → data/memory.db
  │    → 直接展示结果，跳过 Agent
  └─ 普通问题
       → ReActAgent.run：保存历史快照
       → _run：添加用户消息并进入循环
       → 模型生成行动文本
       → AST 解析 → ToolRegistry.execute
       → 天气 / 景点 / MemoryTool
       → 工具结果加入历史 → 下一次模型调用
       → Finish 返回答案
```

MemoryTool 与命令处理函数复用同一个存储对象。记忆能力属于 memory/；tools/ 提供模型可调用的包装；commands/ 提供确定命令的入口。没有为数据库操作新建 Agent。

直接命令不产生模型调用，但当前 main.py 在进入输入循环前仍初始化客户端并读取配置，不能宣称整个应用已支持无模型配置启动。

## 为什么把简单记忆操作从 ReAct 分流

明确的保存、按 ID 更新和删除已具备操作参数，可由程序直接执行。交给 ReAct 时，通常需要模型先选工具，再读取结果组织回复。直接命令返回程序生成的确认文本，省去这些模型调用；没有测量全应用 token 节省比例或延迟收益。

自然语言中少量明确的查看请求通过集合匹配分流。它不能理解任意改写，也不会猜测含糊的修改或删除对象。其他请求仍可能通过 ReAct 的 MemoryTool 完成。

当前直接命令：/remember、/memories、/recall、/update、/forget、/memory-help。修改和删除使用完整 ID；未知斜杠命令返回帮助。main.py 捕获直接记忆操作的 sqlite3.Error 和 ValueError，展示错误后等待下一次输入。

## 历史裁剪与失败恢复

add_message 先添加消息，超限时寻找第二条内部 user 消息的位置，整体删除更早的一轮，直到不超限或只剩当前轮。内部工具结果是 tool 角色，因此不会误判成新轮次。LLM 客户端在发送 API 请求时才将 tool 结果适配为 user Observation 文本。

默认 max_history_messages=20，是软上限；当前轮可能超过它。它按消息数量工作，不计算 token，也没有摘要压缩。

run 在调用 _run 前复制历史列表。成功返回答案时保留新历史；遇到 LLMError 时恢复旧列表并重新抛出异常；_run 用尽步数返回 None 时恢复旧列表并返回未完成提示。保存快照可以恢复本轮中已被裁剪的旧消息，单纯记录列表长度做不到这一点。

快照是浅副本，依赖执行过程不修改旧 Message 字段。恢复只针对上述两种失败情况，不是完整事务；已写入的数据库记录、已执行的工具和费用都不会撤销。

## 存储与检索取舍

- search 使用 SQLite instr，按完整关键词字面包含匹配；不分词、不理解同义词，英文区分大小写，百分号和下划线是普通字符。
- search 默认最多 5 条，直接 /recall 最多 10 条；/memories 最多显示最近创建的 10 条。均按 created_at 倒序、id 倒序排序，不是按语义相关度排序。
- update 保留 ID 和 created_at，没有 updated_at；返回布尔值表示目标记录是否匹配更新。
- delete 只删除数据库记录。当前聊天和模型已经看到的旧内容仍可能留在 history，应在验证删除后使用 /new 或重启排除旧上下文。
- 直接命令不写入 history。仅凭当前历史询问“刚才命令做了什么”可能没有上下文，需要重新查询数据库。
- data/ 已被 Git 忽略，用户记忆不随源码提交。没有备份、加密、多用户隔离或重复记忆合并。

## 验证结果与实际限制

开发与收尾期间使用临时数据库、模拟模型和入口模拟进行了离线断言：

1. 新增、空内容拒绝、缺失 ID、重新建立连接后读取，以及带引号内容的参数化保存。
2. 关键词匹配、无匹配、数量限制、更新后关键词变化、删除后不再检索到，其他记录保持不变。
3. 完整轮次裁剪，保留超长当前轮，清空历史。
4. 工具执行后模型失败的历史恢复、步数耗尽恢复、失败后继续成功执行。
5. ReAct 行动解析经注册表调用 MemoryTool，重新建立 Agent 后使用同一数据库读取、更新和删除。
6. 直接命令、自然语言列表别名和错误参数；模拟 main.py 输入，断言模型 generate 未被调用。

语法检查命令：

```powershell
python -m compileall -q agents core tools memory commands main.py
```

学习过程中用户报告真实模型保存及程序重启后检索测试通过。收尾未重新调用模型、天气或搜索服务，也没有改动实际 data/memory.db。离线模拟不能证明真实模型在所有自然语言请求中正确选择关键词、目标 ID 或操作。

临时断言尚未整理为仓库中的正式自动化测试套件。没有量化准确率、成功率、token 消耗或延迟基准。

其他已知问题：模型写入限制仅依赖提示词，没有独立授权校验；工具 success 仅代表执行未抛异常，不代表找到了目标或业务成功；依赖尚未锁版本；提示词与数据库使用相对路径，需要在项目根目录启动；Ctrl+C/EOF 输入退出处理按用户决定暂缓。旧天气等工具结果仍可能留在多轮历史中，不能将其当作实时信息。

## 学习复盘

能用代码解释的核心变化：

- 模型不会自动记住上一次请求，跨轮能力来自程序保留并重新发送消息。
- 持久化存储、检索和把结果放回模型上下文是不同环节，仅保存数据库还不等于模型能够使用记忆。
- 确定命令适合普通 Python 控制流；需要根据外部结果动态决定下一步的旅行任务继续使用 ReAct。
- 失败时恢复历史与撤销外部副作用是两回事，当前实现只做前者。
- 本版是可解释的单用户记忆原型，不是教材中完整的四类记忆系统。
